Annual EBS pollock assessment workflow

Selected methodological steps from the canonical assessment guide

Use the prior accepted assessment and its archived run as the starting point. AY means assessment year and AY-1 means the previous year. This public selection describes procedures; it does not report current delivery status or assessment results. The 2026 incremental model plan records the executed update order and distinguishes subsequent model comparisons.

Steps to do the assessment

  1. Freeze the starting point. Archive the prior accepted input files, model source and executable, controls, parameter file, report, and projection outputs. Reproduce that run before extending the terminal year. Record objective value, key trajectories, reference points, and the comparison tolerance.
  2. Create an annual run directory. Copy the accepted configuration into a separate AY workspace. Resolve every path in pm.dat, including shared data and control files. Keep the previous accepted run intact.
  3. Start a data delivery register. For each product, record provider, release date, revision, years, spatial coverage, ages, units, checksum, processing script, output file, and status. Distinguish received, checked, incorporated, and accepted.
  4. Update fishery inputs. Reconcile final AY-1 catch, estimate full-year AY catch, and prepare AY-1 catch-at-age, weight-at-age, and composition sample sizes from the EBS sampler. Retain current-year lengths for diagnostics or the accepted terminal-length option.
  5. Update BTS products together. Obtain the bottom-trawl survey index, its matching covariance, age composition, weight-at-age, and sample-size information. Record the estimator and EBS/NBS footprint for each product.
  6. Update ATS and AVO products. Incorporate released summer acoustic-trawl survey products and the acoustic vessel-of-opportunity index. Identify preliminary ages, proxy age-length keys, and missing age deliveries explicitly.
  7. Prepare annual biological schedules. Fit the accepted weight-at-age model after its required fishery and survey inputs pass checks. Update fishery and spawning schedules and retain the accepted maturity, natural mortality, timing, and ageing-error settings unless a reviewed change is specified.
  8. Fit an incremental model sequence. Add catch and fishery inputs first, then survey indices and compositions in separate documented steps. Compare changes in spawning biomass, recruitment, fishing mortality, selectivity, likelihood contributions, and uncertainty.
  9. Finalize and diagnose the assessment. Check compilation logs, exit codes, gradients, Hessian, bounds, residuals, retrospective peels, alternative starts, and required sensitivities. Archive the final fit before preparing projections.
  10. Run harvest projections. Transfer the final population state and biological schedules to SPM/spmR. Update projection years and catch assumptions, then verify the first-year population accounting and the ABC/OFL tables.
  11. Build the SAFE and review package. Generate tables and figures from saved outputs, update review responses and ecosystem material, render in a clean session, and reconcile every management value with the saved assessment and projection files.
  12. Archive the annual release. Retain source snapshots, transformation code, input and output checksums, software versions, seeds, diagnostics, report source, rendered files, and review decisions. Record the final approved advice separately from model-generated maximum values.

Building and checking the assessment model

Fit and preserve the diagnostics

From a copied annual run directory with a verified pm executable and resolved inputs, the historical command is:

./pm -nox -iprint 150 > fit.log 2>&1

Record the command, executable checksum, start file, source/compiler versions, and process exit code. Retain fit.log, pm.par, pm.rep, pm.std, pm.cor, and the gradient/Hessian products written by that build. Some historical make mpd targets remove log, gradient, and admodel.* files after fitting; review the target or use the direct command so diagnostics remain available.

Require a maximum absolute gradient below 1e-4, a positive-definite Hessian, finite uncertainty, and interpretable parameter estimates. Log compiler warnings and resolve them before recording a clean compilation check. A successful exit code establishes execution; the saved diagnostics establish numerical behavior.

Retrospectives and sensitivities

Use terminal-year-consistent peels. Remove observations according to the availability of each stream at that terminal year, including the fishery age lag, acoustic survey schedule, and missing survey years. Truncate the BTS covariance to the same remaining years and extend or truncate biological and selectivity inputs consistently. Recalculate projection schedules for each peel when comparing advice.

Reference points and harvest projections

Harvest recommendation table

Prepare a machine-readable table of advice year, summary biomass and its age definition, spawning biomass, B0/B40%/B35% where required, FABC, FOFL, maximum permissible ABC, recommended ABC, OFL, catch assumptions, and tier. Select values by named output variable, alternative, and year. Verify those selections against the configuration rather than transferring alternative numbers from another stock’s guide.

Generate the AY+1 and AY+2 tables and any decision table of alternative catches from the same saved projection. Check rounding only after the full-precision comparison. Update the risk table and explain any reduction from maximum permissible ABC using the current assessment and ecosystem evidence.

SAFE chapter ecosystem material and annual archive

Update the executive summary, input changes, methods changes, results, diagnostics, reference points, projections, risk table, and responses to review comments from the final run. Retain previous-assessment values in a separate comparison table. Describe the estimator and spatial coverage for each survey and identify preliminary products in the data section.

Render the complete report in an independent clean R session. Check warnings, citations, cross-references, figure descriptions, table units, years, captions, headings, and the final harvest recommendation table. Inspect the Word/PDF layout and retain the agency’s accessibility checks. Keep editable tables as tables and verify figures at their displayed size.

Archive the input and result manifests, source revisions, software environment, build commands, seeds, model diagnostics, report source, rendered review package, final approved chapter, SARA submission products where required, and review decision record. Before committing a selected release bundle, scan code for credentials and internal database connection details. Keep restricted source data within their authorized storage and record how an authorized analyst can obtain them.
