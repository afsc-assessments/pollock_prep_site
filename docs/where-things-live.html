What this edition contains

The annual workflow is selected directly from the existing canonical guide. The incremental-model plan is selected directly from its existing canonical page. There are no independently edited public Quarto copies or downloadable scientific datasets. The internal working website remains available under its existing access controls.

No observational data files are used to build this edition. Years in the model plan are intended input endpoints, not certification of delivery, acceptance or completed model runs. The workflow source was inspected on 9 October 2026; the incremental sequence records instructions supplied on 14 October 2026. These content dates are separate from the build time below.

Reproduce and update this publication

  1. Edit methodological text in its canonical source. For the imported annual guide, edit in the owning project and refresh its canonical saved guide; keep that source relationship recorded.
  2. Review changes to the selected sections and update their exact hashes in public/allowlist.json only after confirming that the public text remains within the approved methodological scope. Unselected text and files are not copied.
  3. Run python3 -m unittest discover -s tests -p "test_public_wiki.py". Preview with python3 scripts/build_public_wiki.py --preview --output-dir /tmp/pollock-public-preview-NEW. Preview output cannot pass a release validation.
  4. Commit the reviewed source and build changes. From a clean canonical checkout, run python3 scripts/build_public_wiki.py --output-dir /tmp/pollock-public-release-NEW, then python3 scripts/public_release.py /tmp/pollock-public-release-NEW.
  5. Use existing authorized account access to publish the exact generated file set to the public output repository. Do not copy the private repository history or the complete internal website. Check the previous output inventory before replacing files; stop on unrelated files or unexpected differences.
  6. Verify the public deployment and all four page URLs anonymously. Confirm that navigation, search and sitemap contain each document once, that inventory hashes match, and that the internal edition retains its existing access controls.

The build requires Quarto 1.10.18, Python 3.10 or later, and the canonical requirements.txt. It uses a fresh staging directory, copies only approved text selections, and regenerates navigation, search and sitemap. The publication validator rejects unexpected files, altered inventory hashes, duplicate pages, broken local links, local machine paths, and known excluded-payload identifiers. Changed selected text requires renewed review and an updated selection hash.

The source repository and internal website links are labeled restricted because they require GitHub/NOAA access. Those links identify ownership; they do not make restricted content public. This publication uses the public URL as its reading address, while the existing private URL continues to serve the internal edition.
